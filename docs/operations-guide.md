# 運用ガイド

## 日常確認

作業開始時に`ai-dev doctor`、`ai-dev validate`、`ai-dev status`を確認します。変更後はformat、lint、型、pytest、Secret scan、依存脆弱性・ライセンスを確認します。

## 状態と監査

ローカル状態は`.ai-dev/local/state.sqlite3`に保存され、Git対象外です。状態遷移、Agent開始・終了、推定費用、承認、停止を記録します。Secretや本番相当データを保存しません。

状態DBのバックアップが必要な場合はタスク停止後にアクセス制御されたローカル保存先へ複製し、保存期限を設定します。Gitや通常Artifactへ置きません。

## 停止・再開

`pause`と`cancel`は安全な工程境界で反映します。`resume`は保存された次状態から再開します。`FAILED`、`BLOCKED`、セキュリティ/データインシデント状態は人間判断なしに自動再開しません。

## コスト

Providerが返す費用は推定値として監査へ記録します。タスク上限到達時は`BLOCKED`になります。正確な費用はProvider請求画面と照合し、月次上限は運用側でも監視します。

## インシデント

Secret検出時は値を再掲せず、対象Secretを失効・再発行し、Git履歴と外部ログへの露出を調査します。データ漏えい疑いではデータ本文を共有せず、専任者が封じ込め、影響範囲、通知、再開条件を決定します。

## 更新

依存のmajor更新、Agent/Prompt、CI/CD、GitHub権限、IAM、ネットワーク、品質基準の変更は人間承認対象です。lockfileとテスト証拠を同じPRへ含めます。
